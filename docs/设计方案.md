# 牛马备忘录 · 设计方案

> 版本：v0.1（规划稿） 日期：2026-09-29
> 技术栈：Vue 3 + ThinkPHP 8 + MySQL 8，联网部署，移动端优先、桌面端自适应

---

## 1. 要解决的问题

你的现状：

- 手上同时有多个**软件项目**和多个**客户项目**，和客户聊出来的需求、自己对项目的想法散落在微信、脑子里、各种文件里。
- 内容形态杂：文字、截图、语音、视频、PDF / Word / Excel / PPT。
- 需要**提醒**：某个需求什么时候跟客户确认、某件事什么时候做。
- 还有大量**不属于任何项目的灵感和琐事**，需要一个随手记的地方。
- 经常在**手机上**操作，所以移动端体验是硬性要求，不是"顺带支持"。

一句话定义产品：**以项目为骨架、以"记录"为最小单位、什么都能往里塞、到点会喊你的个人工作备忘系统。**

---

## 2. 核心概念模型

```
用户 User
 ├── 客户 Customer          （客户项目挂在客户下面，一个客户可有多个项目）
 ├── 项目 Project           （软件项目 / 客户项目 / 个人）
 │     └── 记录 Note        （类型：笔记 / 需求 / 想法 / 沟通记录 / 待办）
 │           ├── 附件 Attachment（图片 / 音频 / 视频 / PDF / Office / 其他）
 │           ├── 标签 Tag
 │           └── 提醒 Reminder（可多个，可重复）
 └── 收集箱 Inbox           （project_id 为空的记录 = 灵感 / 琐事，随手记，之后可归入项目）
```

设计原则：

1. **所有内容都是"记录 Note"**，只用一个 `type` 字段区分需求 / 想法 / 沟通 / 待办 / 笔记。不要为每种类型单独建表，否则搜索、附件、提醒都要写多份。
2. **附件独立成表**，既可以挂在记录下，也可以只挂在项目下（比如客户发来的合同、原型图），项目页有一个"文件"标签页可以按类型浏览。
3. **提醒独立成表**，一条记录可以有多个提醒，也允许没有记录的独立提醒（"周五给张总回电话"）。
4. **收集箱是一等公民**：手机上一键记录，不用选项目、不用填标题，先存下来，有空再整理。
5. **需求有状态流转**：待确认 → 已确认 → 进行中 → 已完成 / 已取消。这是客户项目最有价值的一块，能回答"客户当初说了什么、现在做到哪了"。

## 3. 功能清单

### 3.1 一期（MVP，先跑起来）

| 模块 | 功能 |

| 搜索 | 标题 + 正文全文检索（MySQL ngram），按项目 / 类型 / 标签 / 时间筛选 |

| 桌面端 | 三栏布局（项目树 / 记录列表 / 编辑器） |

### 3.2 二期（用顺手之后补）

- 手机端**语音记录**（MediaRecorder 录音直接上传）、视频录制

### 3.3 三期（锦上添花）

- 语音**转文字**（阿里云 / 讯飞 ASR），录完自动出文字稿

- 导出 Markdown / PDF；项目整包导出
- 记录**版本历史**
- 附件迁移到**对象存储**（OSS / COS）
- 多用户 / 小团队协作
- 离线快速记录（IndexedDB 暂存，联网后同步）

## 4. 技术选型

### 4.1 前端 `web/`

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3.5 + Vite 6 + TypeScript | 你指定 Vue；TS 让接口类型和后端对齐 |
| 状态 / 路由 | Pinia + Vue Router 4 | 标配 |
| UI 组件库 | **Vant 4**（移动优先） | 触屏交互最成熟；桌面端用同一套组件配合自定义三栏布局，不引第二套 UI 库 |
| 样式 | UnoCSS（或 Tailwind） | 响应式断点写起来快，`lg:` 前缀切桌面布局 |
| 编辑器 | **Tiptap 2** | 富文本，手机上比 Markdown 好用；支持图片粘贴 / 拖拽上传、任务列表、代码块；输出 HTML + 可提取纯文本做检索 |
| 请求 | axios + 统一拦截（token、401 跳登录、错误 toast） | |
| PWA | vite-plugin-pwa | manifest + Service Worker，支持"添加到主屏幕"和 Web Push |
| 工具 | @vueuse/core（useMediaQuery 判断桌面 / 手机）、dayjs、browser-image-compression（上传前压图） | |

响应式策略：**一套代码，两个布局壳**。

- `< 1024px`：`MobileLayout`，底部 Tab（今日 / 项目 / ＋ / 提醒 / 我的），页面全屏堆叠式导航。
- `≥ 1024px`：`DesktopLayout`，左侧栏（项目树 + 收集箱 + 提醒 + 标签）、中间列表、右侧编辑器。
- 路由和业务组件完全共用，只是外壳不同。

### 4.2 后端 `api/`

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **ThinkPHP 8.1**（PHP 8.2+） | 你指定 TP |
| 数据库 | MySQL 8.0，utf8mb4，InnoDB | FULLTEXT + ngram 解析器支持中文全文检索 |
| 缓存 / 队列 | Redis（可选，一期可以不上） | 登录限流、推送队列 |
| 鉴权 | JWT（firebase/php-jwt），同时写入 httpOnly Cookie | Cookie 是为了 `<img src>` 加载私有图片时能带上凭证 |
| 迁移 | topthink/think-migration | 建表可版本化，部署时一条命令 |
| 文件 | TP 内置 Filesystem（Flysystem） | 一期本地磁盘，二期换 OSS 只改配置 |
| 图片 | intervention/image | 缩略图、读取宽高 |
| 音视频 | ffprobe（服务器装 ffmpeg，可选） | 读取时长、抽视频封面 |
| Web Push | minishlink/web-push | VAPID 推送 |
| 定时 | TP Command + 系统 crontab（每分钟） | 扫描到期提醒 |

### 4.3 部署

- 一台 2 核 4G 云服务器（阿里云 / 腾讯云轻量即可），Debian 12 / Ubuntu 22.04
- Nginx + PHP 8.2-FPM + MySQL 8 + Redis；可以用 **Docker Compose** 一键起，或者你熟悉宝塔就用宝塔
- 域名 + **HTTPS（必须）**：PWA、Web Push、手机录音（getUserMedia）都强制要求 HTTPS
- 每天 `mysqldump` + 附件目录 rsync 到对象存储做备份

## 5. 数据库设计

```sql
-- 用户（单用户起步，预留多用户）
CREATE TABLE `user` (
  `id`            INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username`      VARCHAR(50)  NOT NULL,
  `password`      VARCHAR(255) NOT NULL COMMENT 'password_hash()',
  `nickname`      VARCHAR(50)  NOT NULL DEFAULT '',
  `avatar`        VARCHAR(255) NOT NULL DEFAULT '',
  `push_config`   JSON NULL COMMENT '推送渠道配置：bark_key / wecom_webhook / email 等',
  `last_login_at` DATETIME NULL,
  `created_at`    DATETIME NOT NULL,
  `updated_at`    DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 客户
CREATE TABLE `customer` (
  `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`    INT UNSIGNED NOT NULL,
  `name`       VARCHAR(100) NOT NULL COMMENT '客户 / 公司名',
  `contact`    VARCHAR(50)  NOT NULL DEFAULT '' COMMENT '联系人',
  `phone`      VARCHAR(30)  NOT NULL DEFAULT '',
  `wechat`     VARCHAR(50)  NOT NULL DEFAULT '',
  `remark`     TEXT NULL,
  `created_at` DATETIME NOT NULL,
  `updated_at` DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 项目
CREATE TABLE `project` (
  `id`          INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`     INT UNSIGNED NOT NULL,
  `customer_id` INT UNSIGNED NULL COMMENT '客户项目关联客户，软件项目可为空',
  `name`        VARCHAR(100) NOT NULL,
  `type`        TINYINT NOT NULL DEFAULT 1 COMMENT '1 软件项目 2 客户项目 3 个人/其他',
  `color`       VARCHAR(10)  NOT NULL DEFAULT '#1989fa',
  `icon`        VARCHAR(50)  NOT NULL DEFAULT '',
  `description` TEXT NULL,
  `status`      TINYINT NOT NULL DEFAULT 1 COMMENT '1 进行中 2 已归档',
  `sort`        INT NOT NULL DEFAULT 0,
  `created_at`  DATETIME NOT NULL,
  `updated_at`  DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_user_status` (`user_id`, `status`),
  KEY `idx_customer` (`customer_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 记录（核心表）
CREATE TABLE `note` (
  `id`           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`      INT UNSIGNED NOT NULL,
  `project_id`   INT UNSIGNED NULL COMMENT 'NULL = 收集箱（灵感 / 琐事）',
  `type`         TINYINT NOT NULL DEFAULT 1 COMMENT '1 笔记 2 需求 3 想法 4 沟通记录 5 待办',
  `title`        VARCHAR(200) NOT NULL DEFAULT '',
  `content`      LONGTEXT NULL COMMENT '编辑器 HTML',
  `content_text` LONGTEXT NULL COMMENT '纯文本，供全文检索与列表摘要',
  `status`       TINYINT NOT NULL DEFAULT 0 COMMENT '需求 / 待办状态：0 无 1 待确认 2 已确认 3 进行中 4 已完成 5 已取消',
  `priority`     TINYINT NOT NULL DEFAULT 0 COMMENT '0 普通 1 重要 2 紧急',
  `source`       VARCHAR(30) NOT NULL DEFAULT '' COMMENT '沟通来源：微信 / 电话 / 面谈 / 邮件',
  `is_pinned`    TINYINT(1) NOT NULL DEFAULT 0,
  `is_archived`  TINYINT(1) NOT NULL DEFAULT 0,
  `done_at`      DATETIME NULL,
  `created_at`   DATETIME NOT NULL,
  `updated_at`   DATETIME NOT NULL,
  `deleted_at`   DATETIME NULL COMMENT '软删除 = 回收站',
  PRIMARY KEY (`id`),
  KEY `idx_user_project_type` (`user_id`, `project_id`, `type`),
  KEY `idx_updated` (`updated_at`),
  FULLTEXT KEY `ft_note` (`title`, `content_text`) WITH PARSER ngram
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 附件
CREATE TABLE `attachment` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`       INT UNSIGNED NOT NULL,
  `note_id`       BIGINT UNSIGNED NULL COMMENT '挂在哪条记录下，可为空',
  `project_id`    INT UNSIGNED NULL COMMENT '冗余项目 id，方便项目文件页查询',
  `file_type`     VARCHAR(10)  NOT NULL COMMENT 'image / audio / video / pdf / word / excel / ppt / other',
  `original_name` VARCHAR(255) NOT NULL,
  `path`          VARCHAR(255) NOT NULL COMMENT '存储相对路径（随机文件名）',
  `thumb_path`    VARCHAR(255) NOT NULL DEFAULT '' COMMENT '图片缩略图 / 视频封面',
  `mime`          VARCHAR(100) NOT NULL,
  `size`          BIGINT UNSIGNED NOT NULL,
  `hash`          CHAR(32) NOT NULL DEFAULT '' COMMENT 'md5，用于去重 / 秒传',
  `duration`      INT NOT NULL DEFAULT 0 COMMENT '音视频时长（秒）',
  `width`         INT NOT NULL DEFAULT 0,
  `height`        INT NOT NULL DEFAULT 0,
  `storage`       VARCHAR(10)  NOT NULL DEFAULT 'local' COMMENT 'local / oss',
  `created_at`    DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_note` (`note_id`),
  KEY `idx_project_type` (`project_id`, `file_type`),
  KEY `idx_hash` (`hash`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 标签
CREATE TABLE `tag` (
  `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`    INT UNSIGNED NOT NULL,
  `name`       VARCHAR(30) NOT NULL,
  `color`      VARCHAR(10) NOT NULL DEFAULT '',
  `created_at` DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_name` (`user_id`, `name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `note_tag` (
  `note_id` BIGINT UNSIGNED NOT NULL,
  `tag_id`  INT UNSIGNED NOT NULL,
  PRIMARY KEY (`note_id`, `tag_id`),
  KEY `idx_tag` (`tag_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 提醒
CREATE TABLE `reminder` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`         INT UNSIGNED NOT NULL,
  `note_id`         BIGINT UNSIGNED NULL COMMENT '可为空 = 独立提醒',
  `title`           VARCHAR(200) NOT NULL,
  `remind_at`       DATETIME NOT NULL COMMENT '下一次提醒时间',
  `advance_minutes` INT NOT NULL DEFAULT 0 COMMENT '提前 N 分钟',
  `repeat_type`     TINYINT NOT NULL DEFAULT 0 COMMENT '0 不重复 1 每天 2 每周 3 每月 4 每年 5 工作日',
  `repeat_until`    DATETIME NULL,
  `channels`        VARCHAR(100) NOT NULL DEFAULT 'webpush' COMMENT '逗号分隔：webpush, bark, wecom, email',
  `status`          TINYINT NOT NULL DEFAULT 1 COMMENT '1 待提醒 2 已提醒 3 已完成 4 已取消',
  `snooze_until`    DATETIME NULL COMMENT '稍后提醒',
  `last_sent_at`    DATETIME NULL,
  `created_at`      DATETIME NOT NULL,
  `updated_at`      DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_scan` (`status`, `remind_at`),
  KEY `idx_note` (`note_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 推送日志（排查"为什么没收到"）
CREATE TABLE `reminder_log` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `reminder_id` BIGINT UNSIGNED NOT NULL,
  `channel`     VARCHAR(20) NOT NULL,
  `success`     TINYINT(1) NOT NULL,
  `error`       VARCHAR(500) NOT NULL DEFAULT '',
  `sent_at`     DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_reminder` (`reminder_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Web Push 订阅（一个用户多台设备）
CREATE TABLE `push_subscription` (
  `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`    INT UNSIGNED NOT NULL,
  `endpoint`   VARCHAR(500) NOT NULL,
  `p256dh`     VARCHAR(255) NOT NULL,
  `auth`       VARCHAR(255) NOT NULL,
  `user_agent` VARCHAR(255) NOT NULL DEFAULT '',
  `created_at` DATETIME NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

说明：

- `note.content_text` 在保存时由后端从 HTML 剥离出来（`strip_tags` + 去多余空白），全文索引建在它上面而不是 HTML 上，搜索结果不会被标签污染。
- `attachment.path` 用随机文件名（如 `2026/09/29/8f3a...c1.jpg`），按日期分目录，原始文件名只存在数据库里。
- 所有业务表都带 `user_id`，即便一期只有你一个人用，将来加人不用改表。

## 6. 接口设计（RESTful，前缀 `/api`）

统一返回：`{ code: 0, msg: 'ok', data: ... }`，非 0 为错误；HTTP 401 触发前端跳登录。

| 模块 | 方法 & 路径 | 说明 |
|---|---|---|
| 认证 | `POST /auth/login` | 用户名密码，返回 token 并写 httpOnly Cookie |
| | `POST /auth/logout` `GET /auth/me` `PUT /auth/password` | |
| 首页 | `GET /dashboard` | 今日 / 逾期提醒、最近编辑、置顶、各项目未完成需求数 |
| 项目 | `GET /projects` `POST /projects` `GET /projects/:id` `PUT /projects/:id` `DELETE /projects/:id` | 列表支持 `type` `status` 筛选，返回每个项目的记录数 / 未完成需求数 |
| | `PUT /projects/sort` | 拖拽排序 |
| 客户 | `GET /customers` `POST /customers` `PUT /customers/:id` `DELETE /customers/:id` | |
| 记录 | `GET /notes` | 参数：`project_id`（传 `0` 查收集箱）、`type`、`status`、`tag_id`、`keyword`、`date_from/date_to`、`is_archived`、`page/limit` |
| | `POST /notes` `GET /notes/:id` `PUT /notes/:id` `DELETE /notes/:id` | 删除为软删除 |
| | `PUT /notes/:id/status` `PUT /notes/:id/pin` `PUT /notes/:id/archive` | |
| | `PUT /notes/move` | 批量把收集箱记录归入项目 `{ ids: [], project_id }` |
| | `GET /notes/trash` `PUT /notes/:id/restore` `DELETE /notes/:id/force` | 回收站 |
| 附件 | `POST /attachments` | multipart 上传，`note_id` / `project_id` 可选；返回 id、访问 URL、缩略图 |
| | `POST /attachments/chunk` `POST /attachments/merge` | 二期：分片上传 |
| | `GET /attachments` | 按 `project_id` / `file_type` 浏览文件库 |
| | `GET /files/:id` `GET /files/:id/thumb` | 鉴权后经 X-Accel-Redirect 下发文件 |
| | `DELETE /attachments/:id` | |
| 标签 | `GET /tags` `POST /tags` `PUT /tags/:id` `DELETE /tags/:id` | |
| 提醒 | `GET /reminders?scope=upcoming|overdue|done` `POST /reminders` `PUT /reminders/:id` `DELETE /reminders/:id` | |
| | `PUT /reminders/:id/snooze` `{ minutes }` `PUT /reminders/:id/done` | |
| | `GET /reminders/calendar?month=2026-09` | 二期：日历视图 |
| 推送 | `POST /push/subscribe` `DELETE /push/subscribe` `POST /push/test` | Web Push 订阅管理、发一条测试推送 |
| | `PUT /settings/push` | 保存 Bark key / 企业微信 webhook / 邮箱 |
| 搜索 | `GET /search?q=&project_id=&type=` | 全文检索 + 附件文件名匹配 |

## 7. 前端页面与交互

### 7.1 路由

| 路径 | 页面 | 手机端 | 桌面端 |

## 8. 文件上传与存储

| 类型 | 处理 |
|---|---|
| 图片 | 前端压缩 → 上传 → 后端存原图 + 生成 400px 缩略图，记录宽高 |
| 音频 | 二期用 MediaRecorder 录音。Android Chrome 产出 webm/opus，iOS Safari 产出 mp4/aac，各自浏览器都能播放；如需跨端统一，服务器用 ffmpeg 转 m4a |
| 视频 | 一期直接上传（Nginx `client_max_body_size 200m`）；二期分片上传（5MB 一片，`upload_id + index`，最后 merge），并用 ffmpeg 抽第一帧做封面 |
| PDF | 浏览器原生打开 / pdf.js 内嵌预览 |
| Word / Excel / PPT | 一期：显示图标 + 文件名 + 大小，点击下载。二期：自建 kkFileView 做在线预览（不用微软在线预览，因为那要求文件公网可访问，客户资料不合适） |

**私有访问（重要）**
客户资料不能被外人猜到链接就下载。所以：

1. 附件存在 `api/storage/uploads/`，不在 Nginx 可直接访问的目录。
2. 前端访问 `/api/files/{id}`，TP 校验 JWT（Header 或 Cookie），通过后返回 `X-Accel-Redirect: /_protected/2026/09/29/xxx.jpg`，由 Nginx 内部 location 高效输出文件，PHP 不用读文件内容。
3. 编辑器正文中的 `<img>` 也指向 `/api/files/{id}`，因为同域 + httpOnly Cookie，浏览器请求图片时会自动带上凭证。
4. 二期切 OSS 时改为私有 Bucket + 签名 URL，接口路径不变。

**存储层抽象**：TP `filesystem` 配置 `local` 和 `oss` 两个 disk，代码只调 `Filesystem::disk(config('filesystem.default'))`，迁移时改配置 + 跑一个搬运命令即可。

## 9. 提醒推送方案

### 9.1 触发机制

```
crontab:  * * * * *  cd /www/memo/api && php think reminder:scan >> runtime/reminder.log 2>&1
```

`ReminderScan` 命令每分钟执行：

1. 查 `status = 1 AND (snooze_until IS NULL OR snooze_until <= NOW()) AND DATE_SUB(remind_at, INTERVAL advance_minutes MINUTE) <= NOW()`，`FOR UPDATE SKIP LOCKED`（防止上一分钟没跑完重复发）。
2. 按 `channels` 逐个渠道发送，成功 / 失败写 `reminder_log`。
3. 不重复的：`status = 2`。重复的：算出下一次 `remind_at`（每天 / 每周 / 每月 / 工作日），`status` 保持 1；超过 `repeat_until` 则置 2。
4. 用户在列表里点"完成"→ `status = 3`；"稍后"→ 写 `snooze_until`。

### 9.2 推送渠道

| 渠道 | 实现 | 适合 | 备注 |
|---|---|---|---|
| **Web Push** | 前端 `pushManager.subscribe` 存到 `push_subscription`，后端 `minishlink/web-push` 用 VAPID 发送，Service Worker 弹通知 | 桌面 Chrome / Edge、Android Chrome | iOS 必须先把 PWA 添加到主屏幕；系统级推送，锁屏可见 |
| **Bark** | `GET https://api.day.app/{key}/{标题}/{内容}?url={记录链接}` | iPhone 用户 | App Store 免费装一个 Bark，最稳的 iOS 方案 |
| **企业微信群机器人** | `POST .../webhook/send?key=xxx` markdown 消息 | 手机、电脑都装了企微 | 建一个只有自己的群，加机器人即可，免费 |
| PushPlus / Server酱 | HTTP 调用，走微信公众号模板消息 | 只想用微信收 | 免费额度有限 |
| 邮件 | SMTP | 兜底 | |

**建议**：一期做 Web Push + Bark（iPhone）或 企业微信机器人（Android / 通用），两条腿走路。推送内容带深链 `https://memo.xxx.com/notes/123`，点开直接到记录。

## 10. 部署方案

### 10.1 目录与 Nginx

前端 build 产物和 TP 的 `public/` 同域部署，一个 server 块搞定，Cookie 也天然同域：

```
/www/memo/
├── api/            ThinkPHP 项目
│   ├── public/     index.php + 前端 dist 拷进来（index.html、assets/）
│   └── storage/uploads/
└── web/            前端源码（仅构建用，可不放服务器）
```

```nginx
server {
    listen 443 ssl http2;
    server_name memo.example.com;
    root /www/memo/api/public;
    client_max_body_size 200m;

    ssl_certificate     /etc/letsencrypt/live/memo.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/memo.example.com/privkey.pem;

    # Vue SPA
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ThinkPHP API：全部交给 index.php，PATH_INFO 保留 /api/xxx
    location ^~ /api/ {
        include fastcgi_params;
        fastcgi_pass  unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_param PATH_INFO $uri;
        fastcgi_read_timeout 300;
    }

    # 私有附件：只能由 PHP 通过 X-Accel-Redirect 触发
    location /_protected/ {
        internal;
        alias /www/memo/api/storage/uploads/;
    }

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|svg|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
server {
    listen 80;
    server_name memo.example.com;
    return 301 https://$host$request_uri;
}
```

TP 路由用 `Route::group('api', ...)`，与上面的 `/api/` 前缀对应。

### 10.2 环境

- **方式 A（推荐，可复现）**：`deploy/docker-compose.yml` 起 `nginx` + `php-fpm 8.2`（装 gd / pdo_mysql / redis / fileinfo 扩展，可选 ffmpeg）+ `mysql:8` + `redis`，数据卷挂 `mysql-data` 和 `storage/uploads`。
- **方式 B**：宝塔面板一键装 LNMP，手动配上面的 Nginx 规则和 crontab。
- HTTPS：certbot 或宝塔自带 Let's Encrypt。
- crontab：提醒扫描（每分钟）+ 备份（每天凌晨）。

### 10.3 发布流程

```bash
# 本地
cd web && pnpm build          # 产出 web/dist
# 服务器
rsync -av web/dist/ server:/www/memo/api/public/
rsync -av api/ server:/www/memo/api/ --exclude runtime --exclude storage --exclude .env
ssh server "cd /www/memo/api && composer install --no-dev && php think migrate:run"
```

写成 `deploy/deploy.sh`，一条命令发版。后面稳定了再上 GitHub Actions / Gitee Go。

### 10.4 备份

```

30 3 * * * rsync -a /www/memo/api/storage/uploads/ /backup/uploads/   # 或 ossutil 同步到 OSS
```

## 11. 安全要点

系统挂在公网，里面是客户资料，这几条一期就要做：

- 强密码 + 登录失败限流（Redis 计数，5 次锁 15 分钟）
- JWT 有效期 7 天，httpOnly + Secure + SameSite=Lax Cookie
- 上传：校验 MIME（`finfo`）+ 扩展名白名单，文件重命名为随机名，禁止 php / html / svg 等可执行或可脚本类型
- 附件目录不在 web 根下，全部经鉴权下发（第 8 节）
- 编辑器 HTML 入库前用 HTMLPurifier 清洗，防 XSS
- 关闭 TP debug，隐藏错误详情；`.env` 不入库
- Nginx 隐藏版本号，只开 80/443/SSH，SSH 改端口 + 密钥登录
- 数据库只监听本机

## 附录 A · 实现说明（2026-09-29 一期落地）

一期代码已按上文落地，以下是实现时与规划稿的差异和补充，以代码为准。

### A.1 语音转文字选型结论

| | 腾讯云 录音文件识别 | 火山引擎 豆包录音文件识别 2.0 |
|---|---|---|
| 免费额度 | **每月 10 小时**，按月重置 | 仅新用户一次性试用额度 |
| 计费 | 开通后默认后付费，不用买套餐 | 按量后付费 0.8 元/小时，也可买资源包 |
| 接口形式 | 异步：CreateRecTask → DescribeTaskStatus 轮询 | 极速版同步：一次请求直接返回文本 |
| 支持格式 | wav / mp3 / m4a / ogg-opus / aac 等 | wav / mp3 / ogg opus |

**默认腾讯云**，两家都实现了驱动（`api/app/service/asr/`），`.env` 里 `ASR_PROVIDER` 一键切换。个人语音备忘每月很难超过 10 小时，基本等于免费。

转写流程：上传音频 → 后端用 ffmpeg 转 16k 单声道 mp3 → 4MB 以内 base64 直传，超过则给服务商一个带 HMAC 签名的临时下载链接 → 结果写回 `attachment.transcript`。前端上传后每 4 秒轮询一次 `POST /api/attachments/{id}/transcribe`，关掉页面则由 crontab 的 `asr:run` 兜底。

### A.2 与规划稿的差异

- **附件表**增加 `transcript / asr_status / asr_task_id / asr_error` 四个字段承载转写结果。
- **手机录音统一转 mp3**：Android Chrome 产出 webm/opus，iOS 产出 mp4/aac，服务端一律转成 mp3 存储，保证跨端可播放且两家 ASR 都能吃。
- **私有文件下发**新增 `FileStreamResponse`，支持 HTTP Range（206），没有 Nginx 时 iOS Safari 也能播放音视频；生产环境 `UPLOAD_ACCEL=true` 走 Nginx `X-Accel-Redirect`。
- **路由**开启 `route_complete_match`，否则 `PUT notes/1/status` 会被 `notes/:id` 前缀匹配吞掉。
- **PHP 8.4+** 的 E_DEPRECATED 在 `AppService::boot` 里屏蔽，不再被 TP 转成异常（本地 PHP 8.5 踩到 `finfo_close`、think-orm 内部写法两处）。
- **快速记录**除文字外支持拍照 / 录音 / 传文件三种入口，先上传附件再建记录，附件通过 `attachment_ids` 在建记录时绑定。
- **记录编辑页**采用自动保存（1.5 秒防抖 + 离开页面时落盘），手机上不用点保存。
- **推送渠道**实现了浏览器通知（Web Push）、Bark、企业微信群机器人三种，邮件未做。
- 开发端口：后端 `php think run -p 8787`（本机 8000 被其他项目占用），前端 Vite 5173 代理 `/api`。

### A.3 关键命令

```bash
php think user:create admin '密码' --nickname=昵称   # 建账号
php think push:vapid                                # 生成 Web Push 密钥
php think reminder:scan                             # 每分钟：到期提醒推送
php think asr:run                                   # 每分钟：转写兜底
```
